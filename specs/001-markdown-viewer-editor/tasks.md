# Tasks: Themed Markdown Viewer & Source Editor

**Input**: Design documents from `/specs/001-markdown-viewer-editor/`

**Prerequisites**: plan.md (required), spec.md (required for user stories), research.md, data-model.md, contracts/

**Tests**: Not requested. Folio has no automated test runner, so this list has no test tasks; validation is manual, per `quickstart.md` and the constitution's verification gates.

**Organization**: Tasks are grouped by user story to enable independent implementation and testing of each story.

**Retroactive record**: Every task is complete (`[X]`). The short hash at the end of each task is the commit that delivered it; where later features replaced the result, the task description says so.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies)
- **[Story]**: Which user story this task belongs to (e.g., US1, US2, US3)
- Include exact file paths in descriptions

## Path Conventions

- Desktop app (Electron): main-process CommonJS modules in `src/`, the esbuild-bundled renderer in `src/renderer/`, bundled documents in `samples/`, and themes in `themes/` (see plan.md → Project Structure)
- `src/renderer/bundle.js` is generated by `build.js` and is never edited by hand

## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: No dependencies. T002–T004 can start once T001 has added the toolchain.
- **Foundational (Phase 2)**: Depends on Setup completion and BLOCKS all user stories. T005–T008 are independent files; T009 needs the store (T005) and the preload script (T008); T010 and T011 build on T009.
- **User Stories (Phase 3+)**: All depend on Foundational completion.
  - Delivered in priority order (P1 → P6), although the real history interleaved them (see Implementation Strategy).
- **Polish (Final Phase)**: Depends on every user story being complete. T057 runs last.

### User Story Dependencies

- **User Story 1 (P1)**: Can start after Foundational (Phase 2), with no dependencies on other stories.
- **User Story 2 (P2)**: Uses US1's render pipeline (T013) to re-render when leaving source mode. The guard in T033 and T035 wraps actions that US1 introduced (T016, T023).
- **User Story 3 (P3)**: Inserts sanitization into US1's `renderPreview()` (T013). T041 reworks the content and export reads used by US2's save (T032) and US6's export (T052).
- **User Story 4 (P4)**: Builds on US1's `loadFile()` (T016) and US2's save and guard (T032, T033) for self-write suppression and the dirty prompt.
- **User Story 5 (P5)**: Can start after Foundational. Its status-bar Outline button (T049) sits in the bar created by US2 (T034).
- **User Story 6 (P6)**: Uses US1's rendered page (T013) and US2's `setSourceMode()` (T029) to leave source mode before printing.

### Within Each User Story

- Tasks are listed in delivery (commit) order.
- Page state and the main-process handler land together when a feature crosses the process boundary, for example `baseUrl` in T025 or `folio-request` in T041.
- Later fixes (T024 → T027, T048 → T050/T051) follow the code they replace.
- Each story is complete before moving to the next priority.

### Parallel Opportunities
