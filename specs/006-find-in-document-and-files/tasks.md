# Tasks: Find in Document & Find in Files

**Input**: Design documents from `/specs/006-find-in-document-and-files/`

**Prerequisites**: plan.md (required), spec.md (required for user stories), research.md, data-model.md, contracts/

**Tests**: Not requested. Folio has no automated test runner, so validation is manual: follow `quickstart.md` and the constitution's quality gates.

**Organization**: Tasks are grouped by user story so that each story can be implemented and tested on its own.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies)
- **[Story]**: The user story the task belongs to (US1–US4)
- Every description gives the exact file path(s) and ends with the commit that delivered it

## Path Conventions

- **Single project**: main-process CommonJS modules live in `src/` and the bundled renderer in `src/renderer/`, both at the repository root.
- There is no `tests/` directory, because the project has no automated tests.
- `src/renderer/bundle.js` is generated by `npm run build:renderer` and never edited by hand.

## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: No dependencies.
- **Foundational (Phase 2)**: Depends on Setup. Blocks User Stories 2–4 only.
- **User Story 1 (Phase 3)**: Depends only on Setup, so it can run in parallel with Phase 2.
- **User Story 2 (Phase 4)**: Depends on Foundational (T003–T005).
- **User Story 3 (Phase 5)**: Depends on User Story 1 (`openFindBar()`, T011) and User Story 2 (the result rows, T019).
- **User Story 4 (Phase 6)**: Depends on Foundational (T003) and User Story 2 (the summary in T019, the box wiring in T018 and T020).
- **Polish (Phase 7)**: Depends on all stories. T031 builds on T004 and T015, and T033 builds on T032.

### User Story Dependencies

- **User Story 1 (P1)**: Independent. It is the MVP and was shipped alone in `2a26dea`.
- **User Story 2 (P2)**: Starts after Foundational and is independent of User Story 1.
- **User Story 3 (P3)**: Joins User Story 1's find bar to User Story 2's result list.
- **User Story 4 (P4)**: Hardens User Story 2 and can be tested on its own with a large scratch folder.

### Within Each User Story

- Markup and styles (`[P]`) come before renderer behaviour; state comes before the functions that use it; event wiring comes last.
- When a story spans both processes, main-process work (`src/folder.js`, `src/main.js`, `src/menu.js`) comes before the renderer work that calls it.

### Parallel Opportunities

- T005 (src/preload.js) can run alongside T004 (src/main.js).
- All of Phase 3 (User Story 1) can run alongside Phase 2.
- In User Story 1, T006 (src/renderer/index.html) and T007 (src/renderer/app.css) can run in parallel.
- In User Story 2, T014 (src/menu.js), T016 (src/renderer/index.html) and T017 (src/renderer/app.css) can run in parallel.
- T032 (README.md) can run alongside T031 and T034 (src/main.js).

## Notes

- `[P]` tasks touch different files and have no unfinished dependencies.
- The `[Story]` label maps each task to a user story for traceability.
- Each user story can be completed and tested on its own, using its quickstart.md scenario.
- This list was reconstructed on 2026-10-18 from the shipped commits. Every task is marked `[X]` and cites the commit that delivered it; `4a9cc98` and `8062af5` contributed only their search-related parts to this feature.
